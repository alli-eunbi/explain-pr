# Report JSON v1

This is the contract between the analyzing agent and the renderer. All prose is plain text, not HTML. Values in `state` are illustrative explanations, never actual customer data. Validated JSON does not prove service correctness or that the author read source code.

```json
{
  "version": 1,
  "sample": true,
  "pr": {"url":"https://github.com/acme/billing/pull/248","title":"구독 갱신 로직 변경","repo":"acme/billing","number":248,"base":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","head":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"},
  "summary":"갱신 결제를 먼저 처리한 뒤 만료일을 연장합니다.",
  "limitations":["결제 서비스 내부는 확인하지 못했습니다."],
  "tests":{"status":"not-run","note":"기존 테스트를 읽었으며 실행하지 않았습니다."},
  "flows":[{
    "id":"renewal","title":"구독 갱신","status":"partial","entry":"request",
    "summary":"구독 요청에서 결과 반환까지.",
    "nodes":[{
      "id":"request","title":"갱신 요청","description":"요청 정보를 받습니다.","changed":false,
      "input":"구독 ID","output":"갱신 요청","before":"","after":"요청 정보를 읽습니다.",
      "state":[{"name":"구독 상태","value":"활성"}],
      "sources":[{"path":"src/renewal.ts","side":"head","start":24,"end":27,"excerpt":"async function renew(id) {"}]
    }],
    "edges":[],
    "findings":[{"id":"save-failure","nodeId":"request","kind":"question","title":"저장 실패 후 처리 확인","condition":"결제 성공 후 DB 저장 실패","behavior":"결제만 완료됩니다.","impact":"재시도 시 중복 결제 가능성을 확인해야 합니다.","sources":[{"path":"src/renewal.ts","side":"head","start":48,"end":51}]}],
    "scenarios":[{"condition":"정상 입력","result":"요청을 받음","assessment":"코드 확인","sources":[{"path":"src/renewal.ts","side":"head","start":24,"end":27}]}],
    "limitations":[]
  }]
}
```

Required report fields: version, sample (boolean), pr, summary, limitations, tests, flows. Optional `lang`: `ko` (default) or `en`; it selects the viewer UI strings and the Markdown report labels. `render --lang` overrides it and is embedded into the rendered data. PR base/head are full 40-character hexadecimal commit SHAs; base is the diff merge-base, not necessarily the target branch tip. Number is a positive integer, repo is owner/name, url is an HTTPS GitHub PR URL consistent with repo and number. GitHub Enterprise host accepted if consistent. `tests.status`: not-run, passed, failed; note always required. `passed`/`failed` require execution evidence for `pr.head`; record the revision, tested scope and CI or user-provided evidence in `tests.note`. Reading tests is not execution.

Flow status: reviewed, partial, unread. All flows require id/title/status/summary/nodes/edges/findings/scenarios/limitations. Unread flows must have nodes=[], edges=[], findings=[], scenarios=[], entry=null and a limitation explaining why. Other flows must have nonempty nodes and an existing entry node. IDs are short unique ASCII identifiers; node and finding IDs unique within flow.

Node required: id,title,description,changed,input,output,state,sources. `changed` is true for changed, false for confirmed pre-existing, null when comparison evidence is unavailable. Never substitute false for an unknown comparison. before/after optional plain strings. State is array of {name,value}, both strings. Every node in a reviewed or partial flow needs at least one source. Sources require path, side (base/head), start/end positive ordered integers; excerpt optional (use it on changed nodes and findings only, one or two lines), must appear inside the range, and must be redacted where necessary. Source URLs generated by renderer from PR host/repo/SHA and encoded path, never supplied as arbitrary URLs. No absolute paths, empty or traversal segments, backslashes, control chars.

Edge shape: {"from":"request","to":"check","label":"유효한 요청","kind":"normal","sources":[source]}. kind is normal or failure; label and sources required. Every endpoint must exist. Two edges between the same pair of nodes are allowed when their `kind` differs (the success and failure outcomes of one call). Cycles allowed for authored retries; traversal must be bounded by user actions, not auto-loop. Entry must reach every node. Multiple outgoing edges are offered to reader as choices; never silently choose a success path.

Finding kind: issue (code-supported defect), question (business policy or missing context). It has nodeId referencing an existing node, title/condition/behavior/impact, and nonempty sources. Findings are not PR approval grades. Scenario fields condition/result/assessment and nonempty sources. Do not use unsourced conclusions; uncertain/unread context belongs in limitations.

HTML template token: __EXPLAIN_PR_DATA__ replaced exactly once with JSON escaped for a script element, e.g. `<` becomes `\u003c`. Token __EXPLAIN_PR_MARKDOWN__ replaced exactly once with a safely encoded JSON string of the matching markdown. The compiled viewer consumes these values from its fixed bootstrap; ordinary report authors do not edit this bootstrap or the runtime bundle. Keep all runtime assets inline and data insertion inert. CLI: `node scripts/explain-pr.mjs validate report.json`; `render report.json output.html [--3d] [--md] [--lang ko|en]` uses `assets/viewer-lite.html` (flowchart only) by default and `assets/viewer.html` (flowchart + 3D follow mode, bundles three.js) with `--3d`, embeds the Markdown in the HTML, and writes adjacent output.md only with `--md`; `source EVIDENCE_DIR base|head PATH [START-END] [--repo LOCAL]` prints a numbered slice of a pinned file; `demo output.html [--lang ko|en]` uses examples/demo.json; `collect PR_URL output-directory` saves metadata.json, diff.patch, files.json (per-file path, added/deleted lines, bytes, hunk file, plus `overBudget` against the coverage budget) and hunks/NNN.patch (one file's diff each). Raw, untrusted local evidence only; no analysis claims from collect.
